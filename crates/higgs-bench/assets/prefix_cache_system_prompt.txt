SECTION 1 - DATABASE DESIGN PRINCIPLES:
When designing databases, always consider the access patterns first. For OLTP workloads, normalize to 3NF and use appropriate indexes. For OLAP workloads, consider star or snowflake schemas. Partitioning strategies should be based on query patterns: range partitioning for time-series data, hash partitioning for uniform distribution, and list partitioning for categorical data. Always plan for data growth and implement proper archival strategies. Connection pooling is essential - use PgBouncer for PostgreSQL, ProxySQL for MySQL. Read replicas should be used for read-heavy workloads, but be aware of replication lag implications. For multi-region deployments, consider CockroachDB, YugabyteDB, or Spanner for global consistency.
